Legenda

Como ler as etiquetas

Gatilho

API → Workflow
O portal chama a API do Workflow Builder (trigger) e o fluxo começa.
API → Web Form
O portal cria uma instância de Web Form pela API.
API → Envelope
O portal cria o envelope direto pela API de eSignature, sem workflow.

Formulário

Formulário do portal
A tela é do próprio portal; os dados vão por API.
Web Form embarcado
Web Form da DocuSign dentro do portal (Docusign JS).
Pré-preenchido por API
Campos chegam preenchidos (formValues), alguns travados.
Regras condicionais
Campos aparecem ou somem conforme as respostas.

Documento

Template eSignature preenchido
Passo “Prepare eSignature Template”: um template com campos é preenchido com as variáveis do workflow.
Doc Gen · Modelo de documento
Passo “Preparar modelo de documento”: o documento é gerado a partir de um modelo da biblioteca “Modelos de documentos”.
Doc Gen por API
Template eSignature com .docx de campos {{Campo}}: o portal cria o rascunho e preenche os campos pela API (docGenFormFields) antes de enviar.

Assinatura

Remota por e-mail
Cada signatário recebe o link por e-mail (SMS/WhatsApp opcional).
Entrega por WhatsApp
O signatário recebe a mensagem da Docusign no WhatsApp e assina pelo celular (deliveryMethod: WhatsApp, sem e-mail).
Embarcada · Focused View ⇄ Clássica
Assinatura dentro do portal. Alterne no seletor discreto “Assinatura: Focused View · Clássica” no canto da janela.
Dentro do workflow embarcado
A assinatura acontece na tela do próprio Workflow Builder (sem opção de Focused View).

Site público

H1

Cotação com assinatura no site

Home → seção Cotação → “Solicitar Cotação + Assinatura Digital” → Assinar agora

Gatilho: envio do formulário → POST /api/docusign/envelope cria o rascunho do template “Proposta de Seguro (Cotacao)”, preenche os campos Doc Gen e envia; “Assinar agora” pede uma sessão de assinatura (/api/docusign/signing-view).

Formulário do portal→API → Envelope→Doc Gen por API→Embarcada · Focused View ⇄ Clássica
  • Melhor exemplo de eSignature API “pura”: sem workflow, o sistema gera o documento e coleta a assinatura.
  • A proposta muda conforme o produto (coberturas, franquias, prêmio com IOF e parcelas). Teste Auto × Vida.
  • Troque Focused View ⇄ Clássica no seletor para mostrar as duas experiências.
H2

“Contrate agora” (onboarding)

Home → seção Como funciona → botão “Contrate agora é fácil”

Gatilho: clique → POST /api/docusign/maestro sem dados → workflow “Onboarding de cliente portal” abre num iframe.

API → Workflow→Web Form (dentro do workflow)→Ramificação por produto→Doc Gen · Modelo de documento→Dentro do workflow embarcado→Salesforce
  • É o mesmo workflow da demo V2; use uma das duas.

Área do Cliente

/area-cliente
C1

Resgate / Portabilidade

Produto PGBL → Resgatar ou portar (ou Serviços → Resgate ou portabilidade)

Gatilho: clique → POST /api/docusign/webforms/instance cria a instância com formValues do perfil (nome, e-mail, CPF, nº do certificado).

API → Web Form→Pré-preenchido por API→Web Form embarcado→Regras condicionais→Template eSignature preenchido→Embarcada · Focused View ⇄ Clássica
  • Nome e CPF chegam travados; “Resgate parcial” mostra o valor, “Portabilidade” mostra entidade e CNPJ.
  • O documento é o template do Web Form preenchido com as respostas (não é Doc Gen).
  • O seletor de assinatura recria a instância no formato escolhido.
C2

Alterar dados cadastrais

Pendências → Confirmar agora (ou Serviços → Atualizar dados cadastrais)

Gatilho: clique → POST /api/docusign/maestro → workflow “Portal atualizacao de cadastro Salesforce” num iframe.

API → Workflow→Web Form (dentro do workflow)→Salesforce: ler→Web Form com os dados do CRM→Salesforce: gravar
  • Não gera documento nem assinatura: mostra integração com CRM sem código.
  • O workflow não recebe dados do portal; o cliente digita no primeiro formulário.
C3

Meus contratos

Menu Documentos, ou Vida Família → Ver contrato

Gatilho: abrir → GET /api/docusign/agreements filtrado pelo CPF do perfil.

API → Agreement Manager→Agreement Manager · IA
C4

Contratação pelo WhatsApp

Bloco Contratação pelo WhatsApp → Ver planos (também no Canal: POP-VP-002)

Gatilho: escolher plano → confirmar celular → POST /api/docusign/whatsapp cria o envelope (template Proposta PF via compositeTemplates) com o titular em deliveryMethod: WhatsApp. A tela consulta GET /api/docusign/whatsapp?envelopeId= a cada 5 s.

Form do portal→API → Envelope→Template eSignature preenchido→Entrega por WhatsApp→Status por API
  • Use o seu celular no perfil de demo: a mensagem chega no WhatsApp em segundos.
  • A trilha avança sozinha: enviada → cliente abriu → assinada.
  • Cópia por e-mail para o e-mail do perfil (papel Corretor).
  • Sem e-mail para o titular: WhatsApp não combina com e-mail no mesmo signatário.

Portal do Canal

/canal
V1

Proposta PF/PJ pelo formulário do portal

Catálogo → Proposta de Adesão → aba “Formulário do portal (API)”

Gatilho: “Enviar proposta” → POST /api/docusign/maestro com 30 variáveis → workflow “Proposta PF/PJ (API)”.

Formulário do portal→API → Workflow→Ramificação PF / PJ→Template eSignature preenchido→Remota por e-mail
  • PF: 1 signatário. PJ: 1–3 representantes + 0–2 testemunhas; papéis vazios são omitidos.
  • Mostre “Ver payload enviado à API” para o time de TI.
  • WhatsApp/SMS é uma opção no passo de envio do workflow (desligada na demo).
V2

Mesma proposta, experiência DocuSign embarcada

Catálogo → Proposta de Adesão → aba “Experiência DocuSign embarcada” → Iniciar

Gatilho: “Iniciar experiência” → POST /api/docusign/maestro → workflow “Onboarding de cliente portal” num iframe.

API → Workflow→Web Form (dentro do workflow)→Ramificação Empresarial / Vida / Auto→Doc Gen · Modelo de documento→Dentro do workflow embarcado→Salesforce
  • Compare com V1: aqui a tela também é da DocuSign; mudar o POP é editar o workflow.
  • Vida usa o modelo “Proposta padrão Vida”; Empresarial e Auto usam “Empresarial e Patrimonial”. Auto não grava no Salesforce.

Focused View não se aplica: a assinatura roda dentro da tela do Workflow Builder.

Aba Acompanhamento

Gatilho: abrir a aba (atualiza a cada 15 s) → /api/docusign/maestro/instances e /api/docusign/envelopes.

Status por API: instâncias+Status por API: envelopes e signatários

Aba Contratos

  • Busca por CPF/CNPJ cruza com o cadastro do CRM (a IA não extrai documento por padrão).

Antes da reunião e se algo der errado
  • Preencha /area-cliente/perfil com seu e-mail e celular (salvo só no navegador).
  • Escolha o formato de assinatura embarcada no seletor “Assinatura: Focused View · Clássica” (fica salvo).
  • Faça login no console DocuSign logo antes (a sessão expira em ~1 h).
  • Tela em “Modo demo”: faltam credenciais no servidor; o roteiro funciona com dados simulados.
  • “Consentimento DocuSign necessário”: abra o link exibido logado na conta demo e aceite.
  • Web Form parado há mais de 5 min: feche e abra de novo (o token expira).
  • “Vence em 30 dias” vazio: rode docs/demos/assets/generate.py e suba os PDFs de novo.
