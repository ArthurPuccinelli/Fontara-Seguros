1A8 min

Proposta de adesão pelo formulário do portal (API)

vendedorWorkflow BuildereSignatureSMS / WhatsApp

Faça

  1. /canal/nova-jornada/proposta → aba “Formulário do portal (API)”.
  2. Clique “Usar cliente de demo”, escolha produto (VGBL) e valor.
  3. Enviar → abra “Ver payload enviado à API” para o time de TI.
  4. Mostre o e-mail de assinatura chegando no seu celular.

Por que importa

  • O formulário é da Caixa; a DocuSign orquestra o resto.
  • Integração com o sistema dos canais por API.
  • Notificação por e-mail e, opcionalmente, SMS/WhatsApp no workflow.

“O vendedor continua no sistema dele. Um POST com o JSON da proposta dispara o workflow: o documento sai preenchido e vai para assinatura.”

Workflow: Fontara Seguros - Proposta PF/PJ (API) · 824dd961…Templates: Proposta PF 8e999bc2…testado 16/11
Por dentro: gatilho, condicionais e o que acontece
Gatilho

Botão Enviar proposta no formulário do portal → POST /api/docusign/maestro com {journey:"proposta", mode:"api", inputs}. O backend autentica por JWT (impersonando o usuário da conta demo), lê o schema em trigger-requirements e chama POST /workflows/824dd961…/actions/trigger.

Regras no formulário (portal)
  • tipoPessoa = PFMostra CPF, e-mail, celular, data de nascimento e beneficiários. Produtos: VGBL, PGBL, Seguro de Vida Individual.
  • BeneficiáriosPercentuais precisam somar 100%; senão o envio é bloqueado.
  • ValidaçãoCampos obrigatórios e formato de e-mail. CPF/CNPJ aceitam qualquer número (sem dígito verificador).
  • numeroProposta / dataPropostaGerados no envio (FS-AAAA-xxxxxx e data de hoje).
O que acontece no workflow
  1. Iniciar (API)
    Recebe as 30 variáveis do portal.
  2. Regra de ramificação
    tipoPessoa contém "PF" (diferencia maiúsculas) → ramo PF.
  3. Prepare eSignature Template
    Template PF: preenche 11 campos travados (nº, data, nome, CPF, e-mail, celular, produto, valor, periodicidade, canal, beneficiários).
  4. Enviar para assinatura
    Remoto. Titular = nomeTitular/emailTitular; Corretor (CC) = quem publicou o fluxo. Notificação por e-mail.
  5. Tela de confirmação
    “Proposta enviada para assinatura” para quem iniciou.
O que o público vê

Cartão de sucesso com o ID da instância, a linha do tempo (gerado → enviado → signatários) e o painel “Ver payload enviado à API”. O e-mail chega em ~10–30 s.

Ganchos para a conversa

Mostre o JSON para o TI; abra o workflow no Workflow Builder e mostre que o envio por Mensagem de texto ou WhatsApp é um checkbox no passo de envio.

Campos Data de nascimento, Endereço e Corretor do PDF ficam em branco (não há variável). Se perguntarem, é só criar a variável e mapear.

“Uma única jornada atende PF e PJ. O workflow decide o caminho e quem assina, conforme os dados preenchidos.”

Template PJ: d47237d8… (Rep 1–3, Testemunha 1–2, CC Corretor)testado 16/11
Por dentro: gatilho, condicionais e o que acontece
Regras no formulário (portal)
  • tipoPessoa = PJEsconde beneficiários; mostra razão social, CNPJ e representantes. Produtos: VGBL, PGBL, Seguro de Vida em Grupo.
  • Representantes: 1 a 3Cada um com nome, CPF, e-mail, celular e cargo (Sócio-administrador, Diretor, Procurador). O 1º representante vira o contato principal.
  • “Exige testemunhas” ligadoAbre 2 testemunhas (nome + e-mail). Desligado: envia as testemunhas vazias.
O que acontece no workflow
  1. Regra de ramificação
    tipoPessoa não contém “PF” → ramo Nenhuma condição atendida (PJ).
  2. Prepare eSignature Template
    Template PJ: razão social, representantes (nome, CPF, cargo), produto, valor, periodicidade, canal, testemunhas.
  3. Enviar para assinatura
    Ordem 1: Representantes 1–3 (em paralelo). Ordem 2: Testemunhas 1–2. Ordem 3: Corretor (cópia).
  4. Roteamento variável
    Papel com nome/e-mail vazio é omitido do envelope. 1 representante sem testemunhas = 1 signatário; 3 + 2 = 5.
Teste de referência (16/11)

2 representantes + 2 testemunhas → envelope com Rep 1, Rep 2, Testemunha 1, Testemunha 2 e Corretor; Representante 3 omitido.

O campo CNPJ do PDF PJ ainda não está mapeado no workflow (a razão social aparece). Evite dar zoom nesse campo ou mapeie cpfCnpj → Cnpj no passo “Prepare eSignature Template” do ramo PJ.

Workflow: Fontara Seguros - Onboarding de cliente portal · 0359ae48…
Por dentro: gatilho, condicionais e o que acontece
Gatilho

Botão Iniciar experiência → POST /api/docusign/maestro com mode:"embedded-workflow" → dispara o workflow 0359ae48… e devolve o instance_url, aberto num iframe dentro do portal.

O que acontece no workflow
  1. Iniciar (API)
    O participante é “quem inicia o fluxo”: quem abre o iframe executa as etapas.
  2. Coletar dados com Web Forms
    Formulário dentro do iframe, com a marca Fontara.
  3. Regra de várias ramificações
    Empresarial / Vida / Auto / nenhuma condição, conforme o produto escolhido.
  4. Preparar modelo de documento
    Doc Gen gera a proposta do ramo escolhido (Auto não tem documento).
  5. Enviar para assinatura → Gravar no Salesforce
    Ramo sem condição exibe uma tela de confirmação.
Comportamento do portal
  • Evento de conclusão (postMessage)O modal troca para “Concluído”. Só aceita mensagens de domínios *.docusign.com / .net.
  • Fechar o modalA instância fica “In Progress” e aparece no Acompanhamento.

Este workflow é o “Onboarding de cliente portal” reaproveitado: o Web Form não pergunta PF/PJ. Use-o para mostrar a experiência embarcada e a edição sem código; a ramificação PF/PJ você mostra no 1A/2.

Gatilho

Card Resgate / Portabilidade → POST /api/docusign/webforms/instance → createInstance no Web Form b5a06678… com clientUserId = e-mail do perfil e formValues pré-preenchidos → o portal monta o form com Docusign JS (instanceToken vale 5 min).

Regras condicionais do Web Form

  • Tipo = PortabilidadeMostra “Entidade de destino” e “CNPJ da entidade de destino”.
  • Tipo = Resgate totalNenhum campo extra.
  • Banco, Agência, ContaSempre visíveis e opcionais.
Depois do envio

O Web Form gera um envelope a partir da cópia do template, com os valores digitados, e segue para a assinatura do Titular. A data da solicitação é preenchida na assinatura. Para editar as regras: Modelos → Formulários da Web → “Fontara Seguros - Resgate/Portabilidade” → campo “Tipo de solicitação” → aba Regras.

Se a tela ficar parada por mais de 5 min antes de abrir, o token expira: feche e abra o card de novo.
